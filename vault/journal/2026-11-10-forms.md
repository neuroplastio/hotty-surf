# 2026-11-10: forms, A7 (L16)

Leg L16 of the a2ui exit, branch a2ui/forms (from main af1e216). The tour's
"One app. Every terminal." sign-up form is the user: fields, a password, a
Strategy choice and Submit. The checkbox (L3, on a2ui/tour) and the slider
(L17) are **left out of the story** (`form/signup`) until they are on main.

## What changed

- **`<form @submit="...">`** (`surfui.Form`, `OnSubmit`): a stack whose
  fields of one line submit it on Enter. hotty's SPEC says what: Enter in
  a text field commits it (`change`), and then submits its form, if it is
  in one (§9, §10.2, V6-03). So a form's field **keeps Enter** (it gives
  the program no `enter=program` any more; `surfui.GivesEnter` is the rule
  now) and the host does both. The cells do what a host does, in the same
  order: the field's `change`, then `submit` with the named controls'
  values in tree order (`pkg/cells/form.go`).
- **`<button submit>`** (`Node.Submit`: `type=submit`) submits after its
  click and after the field the click left has committed. A button with no
  `submit` is `type=button`, as every Button was, and submits nothing.
- **A field of several lines never submits**, in a form or not: its Enter
  is a line break. Along the way: a textarea with a `@change` used to give
  Enter to the program (`enter=program`), which a host then didn't type as
  a newline; `GivesEnter` is for a field of one line only, so a host types
  the break, as the cells do.
- **`label`** on a field is a caption above it, before it in Dense, and
  also its accessible label; **`error`** is a message under it in the
  error tone, which also sets `invalid`. **`type="password"`** is
  `type=password` on a host; the cells already drew `•` for it, and never
  copy it (a test now holds that).
- **How a label and an error are drawn.** The field is one node in every
  API (handlers, `Value`, `Rows`), so a parent draws the caption: when a
  field with a `Label` or an `Error` is added to its parent (`Node.Add`),
  a stack takes its place: `stack [ stack.u-labelled [ label, field ],
  message ]`. The field keeps its key (or is `field`) and so its id,
  `r.kform.kname.0.kname`, as the message comes and goes: a field that
  changed its id would lose the keyboard as the user types. The message has
  the key `error`, so the diff adds and removes it with one op. Dense puts
  the caption before the field (`.u-dense .u-labelled`, a row, the field
  growing); the cells do the same in `look`. **No new CSS property**: the
  rule uses `flex-direction`, `align-items`, `gap` and `flex`, all proven
  (css-subset.md).
  `Label` and `Error` are drawn when the field is added to its parent, so
  a Go builder calls them before that.
- **The checks stay in Go**, in the handler: it reads what the fields
  gave it, sets each field's `error`, and refuses by doing nothing else.
  No validation language. docs/surf.md ("Forms") has the pattern, and the
  conformance fixture `Signup` is it.
- **Both modes, surflua, docs/surf.md ("Forms") and docs/spec.md** (the
  Widgets and Attributes tables, the events table, the cells paragraph,
  the fixtures), a conformance case (`form-signup`, host and cells, in
  Go's two modes and surflua's Lua host), cells goldens (`form-masked`,
  `form-refused`, `form-dense`), the stories `form/signup` and
  `form/errors`.

## Decisions to confirm

- **`label` on a field changed meaning.** It was the accessible label
  (aria-label) of any element, and the brief makes it a drawn caption on a
  field. Six uses in the repository meant the accessible label of a field
  (the gallery's filter and control rows, the settings and palette
  screens): they now say `aria-label`, a new attribute on `field` only
  (`Node.AriaLabel`). A `bare` field (the search rows') keeps `label` as
  the accessible label alone, since it sits inside another control. On a
  `button` and anything else, `label` is as it was.
- **`type`** is a new string attribute on `field` (`text`, `password`);
  `submit` a new bool on `button`.
- **Ids of a labelled field** have two more levels (above). Nothing in the
  repository addressed one.

## Not done

- **A form's `submit` doesn't carry the fields to a handler**: the host
  sends them (`Event.Fields`), the cells too, but `surfrun.Event` has no
  such field, and a handler reads what its component has, since every
  field committed first. A program that wants the pairs would need an
  `Event.Fields` (a surfrun change, not a protocol one).
- **The checkbox and the slider** are in no story yet (L3, L17).
