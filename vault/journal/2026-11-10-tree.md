# 2026-11-10: the tree (L7, A5, G2)

Leg `a2ui/tree`, in Q-0002's answered shape (option 2): a `list` whose
`item`s carry the tree; no `tree` or `treeitem` tag.

## What changed

- **Vocabulary.** `item` takes `depth`, `branch`, `open` and `current`
  (`current` was a button's); `list` takes `keys` (`tree`, the default,
  or `none`). `item` has the events `toggle` and `activate`
  (`Node.OnToggle`, `OnActivate`; the table leg adds the same
  `activate`, so expect a merge touch in vocab.go, node.go and the
  events table).
- **The model owns everything.** hotty-surf draws what `open` says; a
  closed branch's children are absent because the model drew none.
- **The disclosure** is a first child of any item that says `depth`,
  `branch` or `open`: ▸/▾ in the cells, Material's chevron right/down on a
  host, two cells wide, muted, in the ink on the keyboard's row. A leaf
  has the room, so labels line up. Depth is padding-left, two cells a
  level, so fills and the selection's bar keep the left edge. A click on
  a branch's chevron is `@toggle` (value: the item's key).
- **Keys** (`surfui/tree.go`, `resolveTree`): a list with tree items
  binds ↑ ↓ Home End ← → Enter on itself at each resolve, from the rows
  it has then (captions skipped). Each binding is a `surfui.TreeMove`,
  which surfrun runs as the item's own handler: `@click` to select,
  `@toggle`, `@activate`. A key with nothing to run is unbound, so it
  scrolls. `keys="none"` binds none (margin).
- **`:focused`** is not added: the list's selection already follows
  `:focus-within` (bright with the keyboard, quiet without), in both
  renderings, so a pane without the keys shows it dimmed with nothing to
  set. Documented in the Trees sections.
- **Mixed captions and items** from one flat list: a partial whose root is
  an `:if` chain (`<caption :if>` / `<item :else>`), as the conformance
  fixture does (`outline.surf`, `file-row.surf`; the partial's prop is
  `dyn`, since a Lua table is no struct).
