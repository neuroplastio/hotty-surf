# 2026-11-17: the runtime into hotty-surf (L1)

Branch `v07`. L1 fills L0's signatures with the spike's runtime and
closes its gaps. Not pushed: the leg goes to a blind review first.
`api/v0.7.txt` is unchanged, and `make check` passes. Every judgement
call is in `api/notes.md` › L1 notes. `ARCHITECTURE.md` says how the
runtime works inside.

## What is on the branch

- **The root package** renders a templ view, numbers its elements, diffs
  the tree into hotty deltas, and keeps the host's fields and focus.
  - Keys go to the focused element's chain.
  - A press outside, or a blur, runs Outside.
  - Hover, focus and blur have handlers of their own.
  - Hidden inputs aren't fields.
- **The 2 ms floor is gone.** A render whose HTML is unchanged skips the
  parse and the diff. A fast parser builds templ's markup straight into
  a tree and hands anything unusual to x/net/html. FuzzParse and the
  `surfparsecheck` tag hold the two equal. Tasks' acts at 1k rows take
  0.7–1.1 ms, where the spike took about 2 ms (the table is in the
  notes).
- **Tasks and nav wrote the spike's streams byte for byte**, but for
  placing, one focus and the kit's class prefix, until the blind
  review's fixes. Since them the streams differ only by the generated
  ids' prefix and the spaces kept between inline elements; they are
  v07's own baseline now (the notes).
- **run** drives a surface on a hotty host, in cells on a plain
  terminal, and as js/wasm. TinyGo builds Tasks' release wasm with no
  mods (848 KB gzipped), and its stream is Go's byte for byte.
- **surftest** drives a surface on hotty-go's test host. It checks the
  host's document after every act and fails on a render's faults.
- **reload and reload/reloader** give live reload in three tiers (text,
  css, go), over msgpack-RPC, and work with several keys at once.
  **`hotty-surf`** has run, ctl reload, ctl shot, lint and new.
- **cells**, first cut: a hotty host in character cells. What it draws
  is `cells/SUBSET.md`.
- **ui**: Button, Badge, Card, Icon, Kbd, Select, DropdownMenu, Dialog,
  Tabs, Toaster and code.Block, each tested through surftest.
  `internal/spikeui` keeps the spike's popups for Tasks and nav until
  L2.

## How to see it

- `make check`; `make tinygo`; `go test -tags surfparsecheck ./...`.
- `go run ./examples/tasks` (or nav, or hello) in hottyterm, and in a
  plain terminal for cells.
- `go run ./cmd/hotty-surf run examples/tasks` in hottyterm. Edit
  page.templ's heading, and the running app changes.
- `TASKS_ACTS=<dir> TASKS_SIZES=1000 go test ./examples/tasks -run
  TestActs` times the acts.

## What is left for later legs

The board's "Found in L1" lists it. The main items:
- kit.css has no rules for Dialog or Toaster.
- Dialog has no focus trap. Whether hotty needs a modal region is the
  maintainer's question.
- `hotty-surf build` and `serve`, and a headless shot, are L4's.

## The blind review's round

The blind review said "fix first". Its 30 required fixes, its doc changes
and its recommendations are all in, except the one that would reword a
commit message (v07 stays append-only). Each fix comes with its probe
turned into a test that fails without it. In short:

- the runtime keeps spaces between inline elements, leaves an input
  without a value to the host, and restarts a field's rev where the host
  does; a native select is a field; keys reach a page through its
  wrappers; generated ids are `_…`;
- ui's Dialog, menus and Select ask for the keyboard after the render
  and only in their frame; every focus and blur renders;
- cells keeps fields and focus across an inner, and a refused command no
  longer ends the app;
- live reload keeps Tasks' state (bin fields up to 64 MiB), no longer
  hangs or misreports, runs Keep's get on the driver, and builds without
  `go list` when no package can have changed (p50 28.1 ms to 0.16 ms).

`make check` now vets, lints and tests the surfdev build too, and the
goroutine packages pass `-race -count=20`.
