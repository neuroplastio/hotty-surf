# 2026-11-04: tooltips

The board's "Tooltips" item, as the maintainer decided it (2026-11-03:
"tip -> title, but make it a component, not plain text, so tooltip
could be complex. hotty-surf feature", and "OK, makes sense" for the
markup and the `heading` rename). No hotty change: a tooltip is a
surface the host application places from hotty's `hover` (SPEC §9.4),
as it places a context menu.

## What changed

- **Markup.** `title="text"` and `:title` on every widget: the text,
  wrapped. A `<title>` child holds any elements and text, a partial
  too, in the widget's scope (a `:each` row's data), never drawn, and
  no break in a `:if` chain, as `<menu>` isn't. Refused at load: both
  forms on one widget, two `<title>`s, a `<title>` with attributes or
  nothing in it, one outside a widget (a root, a use's children), and
  anything that acts in one: a control, an `@` handler, a `<bind>`, a
  `<menu>`, `focusable`, `autofocus`, `drag`, `drop`, an `<embed>`, a
  tooltip in a tooltip, in the partials it uses too (told at the use).
- **`section`'s heading is `heading`.** `<section title=…>` with no
  `heading` is refused until 0.3, with the hint. The Go `surfui.Section`
  takes `heading`; the gallery's section story, the spec's tables and
  docs say it. No `.surf` here or in plx used `section title=`.
- **A partial's use** keeps its attributes as props.
- **surfui:** `Node.Tip(content)`, `Node.Title(s)`, `TipOf`, `HasTip`,
  `TipCard` (the tip's surface root, in the element's theme and density:
  a `u-tip u-small` card, a text directly in it wrapped), `TipID`,
  `TipCols` (48). surf writes no HTML `title`; every element has an id.
  The card's CSS is one block of its own at the end of surf.css: the
  open list's raised fill and hairline, without its shadow.
- **surfrun:** `Surface.Tip(TipAt) (Tip, bool)`: the innermost
  element's tooltip around `TipAt.ID` (a hover's target, or
  `cells.Renderer.At`'s), from the fresh tree; false for none or a stale
  id. `Tip` has `ID`, `Tree`, `HTML(sheets...)`, `Cols`×`Rows` for a
  host, and `Cells` (a `cells.Screen`). `Frame.Hover` is `hotty.On` or
  `Off`: Show's says it, an Update's when it changes. A `hover` event
  goes to no handler.
- **cells:** `cells.DrawTip`: the card with a line round it, as the
  open list has, at its natural width up to 48, wrapped.
- **Docs:** docs/surf.md ("Tooltips"), the spec ("Tooltips", load
  errors), the guide ("Hosting without surfrun.Runtime", "Tooltips":
  the host's recipe).

## Where the board was silent

- **`TipAt` is `{ID}`** only: a hover's `t` and `cells.Renderer.At`
  both give an id. The keyboard is out of the first cut.
- **Two sizes.** A host's card has half a cell of room above and below,
  the cells' a line: `Tip.Rows` is `Tip.Cells.Rows` less one, the cols
  the same, measured by the cells' layout.
- **The runtime shows no tooltips** and asks for no hover, as it shows
  no context menu: no host in this repository places menus, so there is
  no reference implementation; the guide has the recipe.
- **`pointer-events: none`** is the host's sheet on the tip's document
  (`html { pointer-events: none }`): surf's sheet can't reach `html`
  for one document only.
- **What acts** is the controls (`button`, `field`, `switch`, `select`,
  `cycle`) and the rest above; `<embed>` too.
- **An empty `title`** (`:title` that is `''`) is no tooltip; a
  `<title>` whose children draw nothing at a render is none.
- **Lua:** surflua doesn't expose `Menu`, so it doesn't expose `Tip`.
