# Touch areas in the cells (SPEC §9.6; docs-surf's gap: the tour's cells slider)

`cells.Screen.Touch` is where a finger drags as the mouse does: a
slider's track, across (`"x"`, the track alone, not the value after it),
and any other drag handle either way (`"xy"`), in the order drawn, so the
last listed decides where they overlap. A disabled handle has none, and
neither does what an open Select's list covers (those cells are the
list's). At most `hotty.TouchMax` (256) go on a screen. `Screen.same`
compares them, so a changed area is a new generation.

`surftea.Host.Touch()` has them as of the last `Lines`, from the
rectangle's top left. Sending them is the host's: add the rectangle's
column and row to each and send `hotty.Touch(areas)` (a=touch) when they
change, and an empty one (or none) to leave none, since an area works only
while the program has the terminal report the mouse (§9.6).

Also: `Renderer.Scroll`'s doc says that the zero value does not scroll the
page in cells (docs-surf found it by Wheel returning false); the default
is unchanged.
