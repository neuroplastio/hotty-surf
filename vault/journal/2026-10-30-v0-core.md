# 2026-10-30: v0's core, its compiled mode, the fixes, WebAssembly

The maintainer picked R-23's candidate A with `.surf` templates (gov
NEIO-15). This leg is everything on main up to 0d4f134.

## What changed

- The project is hotty-surf, package `surf` (8c89236). B and C are out
  of the tree.
- `.surf` templates, interpreted on cel-lite (1a0ae0e); `surfgen` writes
  the bindings, and `conformance/` holds the cases both modes must pass
  (1cb3bea). `docs/surf.md` is the reference (679ceaa).
- The compiled mode (c2d5ba8, 27d282a): `surfgen` writes a Go function
  per template and owner, and runs a template's own program for what Go
  can't say exactly. A dyn prop that doesn't fit its type is an error in
  both modes, and the prop takes its zero.
- `make bench` (df3046d), which check doesn't run.
- The verdicts' fixes (33eaea0): cursors, a Select whose list the
  runtime draws, a Field that commits on Enter and on leaving it.
- WebAssembly (7f250f2): `make wasm`, in check.

## How to see it

- `make check`; `make bench` for the render cost of a 50-note board
  (161 µs compiled, 315 µs interpreted on this machine).
- `go test ./conformance -run TestCases -v`: each case, once per mode.
- `vault/knowledge/wasm.md` for the sizes.
