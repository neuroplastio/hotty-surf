# 2026-11-16: v0.7's shape as signatures (L0)

Branch `v07`, off v0.6.3. The plan of 2026-11-16 moves hotty-surf onto Go,
templ and Basecoat; L0 freezes the shape before any of it moves in. Not
landed, not pushed: the maintainer approves the v0 API pack first.

## What is on the branch

- The v0.6 packages are gone from the branch (main keeps them at v0.6.3).
- The v0.7 API as signatures, bodies `panic("L0")`: `surf`, `ui` (the
  component pattern on one component of each kind), `ui/code`, `run`,
  `cells`, `surftest`, `lint`, `reload`, `reload/reloader`, and `surftea`
  as a module of its own. An example per package; `examples/hello`, an
  app with a .templ view, written against them.
- The API lock: `api/v0.7.txt` (approved, empty until the pack is),
  `api/next.txt` (generated), `api/reasons.md` (a line per name),
  `api/notes.md` (the pack's opening). `make api`, `api-check` (in
  `make check`), `api-frozen` (CI on main), `api-approve`, `pack`;
  `internal/apitool` writes the pack page.
- `ui/coverage.tsv` and `docs/coverage.md`: Basecoat 1.1.0's 39
  components, how each is made, its names, stories and tests.

## Where the shape departs from the plan's draft

No `embed` (the root's Surface owns no terminal and is the embedding
API), no `wasm` (run.App under js/wasm), `surftea` not `embed/tea` (the
`tea` name collides with Bubble Tea's). `lint`, `reload` and
`reload/reloader` are plx's asks: plx plugins are Go now and plx runs the
dev loop for them, building against these signatures before L4.

## Learned

- Basecoat 1.1.0's select.js has no search box and no typeahead, and
  dropdown-menu.js no typeahead: the first signatures claimed both.
- Basecoat's default variant is `primary`: `ui.Primary` is Variant's
  zero value.
- staticcheck reads a body that panics as never returning, so a value
  made by an L0 function looks unused (SA4006): one ignore, with its
  reason, in examples/hello until L1.
- TinyGo 0.43 builds templ, x/net/html and the spike's diff for js/wasm
  byte for byte as Go does, at about a third of Go's gzipped size; the
  numbers are in NEIO-15.

## The gate (later the same day)

The maintainer approved the shape and delegated the calls ("let's trust
it. Let's apply the leans"). Applied as written: the blind reviewer's
review (C1 cells as a writer of hotty commands, C2 the placement flags
and one command per Write, C3 reload.Serve inline with the instance key)
and plx's plugins agent's review (one reloader per directory, processes
dialing in by key, Tags, Output, Env, Report.Failed); every open question took the
reviewer's lean (api/notes.md, "Decided"). `make api-approve` put the
result in api/v0.7.txt: 171 names, the lock L1 builds against.

## The verifier's fixes

A fresh reviewer, the verifier, checked the applied API against both reviews.
It was all applied except Q2's lean for the toast: Basecoat's toast has
categories, not variants, so `ui.Toast.Variant` became
`ui.Toast.Category` (the lock re-approved, one line). The rest were doc
contracts L1 would otherwise have settled in code: which goroutine
Keep's get runs on, a process that leaves isn't a crash, cells calling
back into a surface from inside its Write, View set through Do, run's
and reloader's docs agreeing, the right SPEC sections, Badge's six
variants. AGENTS.md and the README now describe v0.7; v0.6's guides
(the guide, the `.surf` reference and spec, components in Go) are gone
from this branch and stay with v0.6.3. What wasn't doc-only is in
api/notes.md, "Notes for L1".

## The lock

The verifier's verdict is LOCK. The last change before L1 is a name: the
dev command is `hotty-surf` (`cmd/hotty-surf`: new, run, ctl, lint,
shot, build --wasm, serve, book), and its environment variables and
files are `HOTTY_SURF_…`. The plan had `surf`, which the standing rule
against a bare `surf` rules out. That closes L0.
